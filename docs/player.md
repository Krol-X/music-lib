# MPRIS-мост

Сервер хранит только файлы и метаданные; состояние воспроизведения решено не
заводить на сервере. Поэтому пульт сделан рядом, в `player/bridge.mjs`: процесс,
который сам является плеером — снаружи это `org.mpris.MediaPlayer2.musiclib`,
внутри mpv играет треки по HTTP-стриму сервера.

Смысл конструкции: пульт не нужно писать. Обладающий обложками и попапом виджет
`omarchy.media` в баре Omarchy — обычный MPRIS-клиент, он находит любой плеер на
session bus и рисует его трек, исполнителя и кнопки prev/play/next. Мост просто
становится для него очередным плеером.

Состояние переживает рестарт юнита: на SIGTERM в
`~/.local/state/music-lib/player.json` пишется «кто играл и на какой секунде», на
старте мост поднимается как Paused на той же секунде и **не запускает звук сам** —
рестарт юнита не должен включать музыку. Это состояние клиента, в базе
библиотеки его быть не должно.

## Решения

| деталь | решение |
| --- | --- |
| воспроизведение | mpv `--idle=yes`, живёт между треками, команды по JSON IPC unix-сокету |
| очередь | `GET /tracks?limit=200&sort=title&order=asc`, по кругу (`LoopStatus=Playlist`); порядок задаёт виджет (см. ниже) |
| состояние | держит мост, а не mpv: Metadata/trackid и переходы — логика плеера, рестарт mpv не сбивает «что играет» |
| пауза | своя переменная, события mpv — только сверка: `pause=false` на mpv по умолчанию, property-change при этом не рождается |
| конкурент | пакет `mpv-mpris` подкладывает `/etc/mpv/scripts/mpris.so`, и наш mpv сам регистрирует второй MPRIS с `CanGoNext=false` и без обложки; omarchy.media выбирает его активным. Лечится стартом mpv с `--load-scripts=no` — только у нашего экземпляра, у mpv пользователя плагин остаётся |
| обложка | `mpris:artUrl` = `http://127.0.0.1:3000/cover/:id`, тянется с сервера |
| переход | `loadfile replace`; по `file-loaded` шлётся `Seeked(0)` — скачок позиции |
| резюм | `loadfile … -1 {"start":"<сек>"}` — у mpv 0.38+ опции только четвёртым аргументом и только строками |
| сигналы | скачок `playback-time` больше 1,5 с = seek → мост шлёт `Seeked(позицию)` из спеки; без него клиент продолжает тикать от старого места |
| учёт | тик раз в секунду считает только пока mpv реально играет; на 30-й секунде звучания (короткий трек — дослушан целиком) идёт `POST /tracks/:id/play`, не дожидаясь перехода: «недавно прослушанные» поднимает трек по-живому |

## Порядок очереди задаёт виджет

Quickshell не умеет задавать произвольные D-Bus-свойства, поэтому режим
сортировки живёт отдельным unix-сокетом рядом с push-каналом. Виджет пишет
строку `mode [asc|desc]` на смену вида, мост пересортировывает очередь теми же
ключами, что и список.

Один и тот же сокет работает в обе стороны: мост шлёт `now <id>` при каждой
смене трека и сразу на подключении клиента. Так виджет узнаёт id играющего —
единственным доступным способом, см. [widget.md](widget.md#подсветка-текущего).

До первого сообщения от виджета очередь считается `title/asc` — дефолт обязан
совпадать с первым пунктом меню, иначе Next пошёл бы не по видимому списку.

Очередь живая: перед каждым переходом (next/previous, включая автопереход по
концу трека) список перечитывается с `/tracks`, поэтому залитый трек появляется
без рестарта, а удалённый исчезает сам. Провал обновления не роняет
воспроизведение — играет то, что уже есть.

## Грабли

Тонкости, на которых легко ошибиться (и на которых было ошиблено):

- файл при `replace` сначала закрывает старый: `end-file` успевает сбить «файл в
  плеере» раньше, чем загрузится новый, поэтому `file-loaded` возвращает этот
  признак на место;
- `Position` по спеке не рассылается через PropertiesChanged — только Get;
- значения словаря `mpris:metadata` обязаны быть Variant'ами: marshalling `a{sv}`
  простой строки не заворачивает и падает с внятной, но неожиданной ошибкой
  пары `[signature, data]`;
- на bun у dbus-next есть класс `Interface` и его статический
  `emitPropertiesChanged()` — в `dbus-next/lib/service/interface.js`; трогать его
  надо именно с капитально импортированного класса, `dbus.Interface` в ESM пуст и
  молча роняет рассылку: виджет зависал на первом состоянии;
- у сигнала в классе должно быть **тело-метод**, возвращающее аргументы
  (`Seeked(us) { return us }`) — `configureMembers` оборачивает его в отправку;
  без тела `options.fn` undefined и каждое издание сигнала тихо роняет обработчик
  событий mpv, умирают **все** последующие события (позиция замирает, пауза не
  сверяется).

## Запуск

Переменная `MUSICLIB_SERVER` (по умолчанию `http://127.0.0.1:3000`),
`SIGTERM`/`SIGINT` закрывают шину и гасят mpv.

```sh
bun player/bridge.mjs
```

В systemd ставится автоматически через `mise run install`. Путь к проекту и к
bun подставляет `scripts/install.sh` в шаблоны `systemd/*.service.in`.
