# Виджет в баре Omarchy

Виджет из бара открывается кликом (левый — play/pause, правый — попап). В клоне
`omarchy.media` под попапом добавлен плейлист библиотеки, а вокруг — полный
CRUD.

Исходники: `desktop-plugin/krol.media/`. Живут они в
`~/.config/omarchy/plugins/krol.media/` — и это должен быть **симлинк** на
репозиторий, а не копия. `mise run install` ставит именно ссылку; копия
разъезжается с исходниками, и правки виджета молча не доезжают.

## Решения

| деталь | решение |
| --- | --- |
| список | `XMLHttpRequest` из QML на `GET /tracks?limit=200&sort=title&order=asc` — та же база, что берёт очередь моста |
| клик по строке | левый — играет этот трек (`player.openUri` → опциональный `OpenUri` моста, работает и из Stopped); правый — форма правки |
| видимость секции | виджет посвящён библиотеке целиком: клонированный `Service.qml` режет список MPRIS-плееров до нашего моста — браузер и прочее в виджет не попадают |
| перемотка | слайдер `PanelSlider` с временем по краям; по отпуску — писабельный `player.position = value` (`SetPosition`, gated по trackid на мосте). Нюанс quickshell: `position` не перетикает сам — держим `Timer`, который вручную издаёт `positionChanged()`, пока играет и попап открыт |
| громкость | слайдер рядом с перемоткой: `Volume` из MPRIS писабельный, мост гонит его в mpv и обратным ходом — mpv-клавиши не рассинхронят слайдер |
| повтор | глиф честен насчёт режима: перечёркнутые стрелки — выкл, круговые — весь плейлист, стрелки с «1» — один трек; цикл None → Playlist → Track → None |
| обложки строк | `SizedImage` с `/cover/:id?w=64` (серверное превью `?w=` через sharp) |
| заливка | кнопка «залить» → `zenity --file-selection --multiple` → `python3 uploader.py` из `Io.Process` (XHR QML не умеет бинарный multipart) |
| правка | форма вместо списка: четыре поля `TextField` — title/artist/album/genre, пустая строка = очистить поле; сохранение — PATCH |
| удаление | в той же форме, в два нажатия: первое меняет кнопку на «точно удалить?» |
| учёт прослушивания | штамп «dd.mm.yy HH:mm» у строки в режиме Recent, дата заливки — в Newest. Сервер пушит событие в `music-lib-push.sock`, плюс контрольный поллинг раз в 15 с |

Почему не MPRIS-интерфейс TrackList: у него своя возня с событиями
TrackAdded/TrackRemoved и его клиент получается объёмным, а клик-по-строке
решается одним опциональным методом у Player, которым же умеет любое
MPRIS-приложение.

Мелкость: `XMLHttpRequest` от `file://` внутри шелла пустой (это знал ещё
плагин omarchy), но на `http://127.0.0.1` ровно то, что нужно — сеть явная и
локальная, по правилам Plugin UI Safety omarchy.

## Подсветка текущего

У `MprisPlayer` в Quickshell **нет свойства `trackId`**, хотя мост отдаёт
`mpris:trackid` по спецификации. Не пробросить его в QML нельзя, а `mpris:artUrl`
есть не у каждого трека (нет обложки — нет artUrl). Поэтому id приходит в
виджет отдельным каналом: мост пишет `now <id>` в сортировочный сокет, виджет
читает это через `SplitParser`.

Фоллбэк по тегам (`title`+`artist`) остался только для случая, когда id ещё не
пришёл, и срабатывает **только при единственном совпадении**: при дублях
названий подсветка не вешается ни на одну строку, вместо чтобы врать про
первую. У библиотеки полно треков с одинаковыми тегами (разные рипы одного
альбома, `Part 1` и `Part 2` с одинаковым заголовком) — для них порядок и
подсветка идут по id.

## Сортировка

Меню предлагает три режима: **Title**, **Recent**, **Newest**, плюс кнопка
направления ↑/↓. Меню рисуется на месте плейлиста (в QML селекта нет, а
вложенное окошко к попапу не привязывают).

В режиме Recent непрослушанные треки **не показываются вообще**, а не
уезжают в конец. Мост повторяет это поведение: иначе очередь держала бы 200
треков, пока в попапе их 15, и Next играл бы то, чего в списке нет.

Режимов Album и Artist нет намеренно. Альбом тянул составной ключ
artist → album → disc → track, которого в виджете нет, и порождал то самое
расхождение порядков. Фильтры по альбому и исполнителю планируются отдельной
штукой, как на сайтах, и не должны влиять на порядок очереди.

## Почему порядок обязан совпадать

Next обязан идти ровно по нарисованному списку, и на этом ломалось. Причины
были три, и все три пришлось закрыть:

**1. Разные базы у сервера.** Виджет брал `sort=album`, мост — `sort=title`.
Сервер сортирует в SQLite посимвольно, виджет пересортировывает в JS через
`localeCompare`, который **игнорирует знаки препинания**. На паре `Breathe (In
the Air)` и `Breathe In The Air` SQLite ставит скобку раньше, а JS — позже, и
список разъезжался на пару позиций: в попапе не было двух треков `Blind Eye`,
которые ставил мост.

Убрали режим album, и база стала общей (`sort=title` у обоих).

**2. Нестабильный порядок равных.** У `Array.sort` нет гарантии порядка равных
элементов, а у библиотеки полно треков с одинаковыми тегами. Теперь последним
ключом везде стоит `id` — он уникален, и порядок внутри группы детерминирован.
Направление сортировки пользователя в этот ключ намеренно не доходит: внутри
группы по названию, а не наоборот.

**3. Разное поведение Recent.** Описано выше.

Ещё рядом с этим нашлись две ошибки, которые выглядели бы как возврат того же
бага:

- в режиме Title ключи `artist`/`album` сравнивались голым `localeCompare`,
  который не был пропущен через `flip`. При `desc` заголовок сортировался вниз,
  а эти два ключа — по-прежнему вверх;
- массив `names` в `notifyQueueSort()` разошёлся с индексами `sortIndex` после
  удаления Artist, и при Newest виджет слал мосту `recent`.

Компаратор в QML и в `orderTracks` моста обязан совпадать **посимвольно**. Это
два места с логикой сортировки, и они разъедутся снова — поэтому при правке
одного надо смотреть и в другое.

## Скролл

Список не центрируется при каждой смене трека: если строка уже целиком в окне,
он не трогается вовсе; если вышла за окно — трек ставится в середину.

Прижим к краю не годится: следующий соседний трек тут же снова оказывается за
границей, и список ползёт за каждым треком. Замерено на числах: прижим к низу
даёт 11 сдвигов на 11 переходов, середина окна — 3.

## Зависимости виджета

`python3` (заливка через `uploader.py`), `zenity` (диалог выбора файлов),
quickshell. Всё это проверяет `mise run doctor`.

## Загрузка оболочкой

Оболочка держит уже загруженный QML и не подхватывает файл сама. После правки:

```sh
mise run pull-plugin
```

Скрипт пересоздаёт симлинк, чистит кэш QML и просит оболочку перечитать
плагины. Без сброса кэша правка выглядит как «ничего не изменилось» — QML
исполняется из скомпилированного кэша, и в журнале видно старые строки.
