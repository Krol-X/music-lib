# HTTP API

Сервер отдаёт библиотеку наружу и ничего больше не делает: состояние
воспроизведения, очередь и позиция живут на клиенте (см. [player.md](player.md)).
Поэтому API — это «список файлов и метаданных», без единого маршрута про то,
что играет сейчас.

Приложение собирается в `src/app.ts` как `buildApp(db)`: база передаётся
параметром, а не импортируется синглтоном. Благодаря этому тесты подменяют её
временной базой и гоняют хендлеры через `app.handle()`, не создавая боевой
`storage/`. `src/index.ts` остаётся только точкой входа: порт, миграции,
обработчик остановки.

## Маршруты

| маршрут | что делает |
| --- | --- |
| `GET /tracks` | список: пагинация, поиск, фильтры, сортировка |
| `GET /tracks/:id` | один трек |
| `POST /tracks/:id/play` | отметка факта прослушивания (см. ниже) |
| `PATCH /tracks/:id` | точечная правка закладных треков |
| `DELETE /tracks/:id` | удалить трек: строка и файлы (opus, обложка) |
| `POST /audio/upload` | загрузка файла: конвертация, теги, обложка |
| `GET/HEAD /audio/:id` | стрим готового Opus |
| `GET/HEAD /cover/:id` | обложка, если есть |

## Параметры `GET /tracks`

```
?limit=50    потолок 200, мусор откатывается на 50 (виджет не тянет 10k разом)
?offset=0
?q=...       поиск подстрокой по title, artist, album, genre
?artist=...  точное совпадение, регистр не важен
?album=...
?genre=...
?sort=created|title|artist|album|year|duration
?order=asc|desc (по умолчанию created desc)
```

Ответ: `{ items, total, limit, offset }`, элементы с camelCase и готовыми URL
(`audioUrl`, `coverUrl`), без внутренних путей на диске. sqlite отдаёт boolean
как 0/1 и время как `"YYYY-MM-DD HH:MM:SS"` — в JSON оба переводятся (ISO с Z,
потому что `CURRENT_TIMESTAMP` в sqlite UTC).

Сортировка по `album` включает весь составной ключ: artist → album → disc_no →
track_no, иначе треки одного названия раскидаются в хаотичный порядок,
диктуемый id. По nullable-колонкам null уезжает в конец выборки. Поиск `q`
экранирует `%` и `_`, поэтому это литералы.

> Серверная сортировка и сортировка в виджете — разные вещи, и это уже умело
> разъезжаться: SQLite сравнивает посимвольно, а JS `localeCompare` игнорирует
> знаки препинания. Подробности в [widget.md](widget.md#сортировка).

## Стриминг

`GET /audio/:id` отдаёт готовый Opus с поддержкой Range, `HEAD` — только
заголовки. Без Range браузер скачивает файл целиком, чтобы найти момент для
перемотки, поэтому `<audio controls>` без seek. С Range приходит только нужный
кусок, и перемотка становится мгновенной.

| запрос | ответ |
| --- | --- |
| без Range | 200, весь файл |
| `bytes=0-99` | 206, `Content-Range: bytes 0-99/<размер>` |
| `bytes=500-` | 206, от 500 байта до конца |
| `bytes=-200` | 206, последние 200 байт |
| начало за концом файла | 416 с `Content-Range: bytes */<размер>` |
| мусор или несколько диапазонов | 200, весь файл |
| неизвестный id | 404 |

Путь к файлу берётся из БД по id, а не собирается из него, поэтому подставить
`../../etc/passwd` нельзя: несуществующий ключ просто даёт 404.

Разбор заголовка вынесен в `src/audio/range.ts` и покрыт тестами: там грабли с
границами диапазона, и на них легко ошибиться.

Не сделано намеренно: `ETag` и `Cache-Control: immutable` не выставлены. При
смене политики битрейтов тот же id получит другое содержимое, и иммунитетный кэш
отдал бы игроку старый файл. Сейчас стоит `private, max-age=3600`.

## Правка и удаление

`PATCH` правит только присланные поля, пустая строка очищает поле (null в
схеме не заводим: exact-mirror в этом exp-билде Elysia ругается на Union на
каждом запросе). После правки `meta_source` становится `edited` — это уже не
догадка по имени файла, а то, что человек подтвердил сам. Год проходит
валидацию по диапазону 1000–3000, как и в тегах.

`POST /tracks/:id/play` — факт прослушивания. Решает клиент: мост честно
признаёт трек прослушанным только после 30 секунд реального звучания (короткий
трек — если дослушан целиком), сервер лишь ставит штамп и растит счётчик.
Тем же POST-ом доносится фактическая длительность, если в БД у трека дыра —
разовое заполнение.

Обработка ошибок единая через `app.error("global", ...)`: любой провал
возвращает `{"error": "..."}` тем же JSON. HTTP-статус уже выставила Elysia:
404 для NotFound, 400 для ParseError, 422 для ValidationError, 500 для
остального — мы его не переопределяем.

`DELETE` удаляет строку первой, файлы — следом по путям из БД (`opus_path`,
`cover_path`): оборванный между двумя шагами процесс оставит сироту для
будущего сканера, а не трек, указывающий в никуда. Подтверждения нет: мусорку
заменить дешевле, чем писать, чем реальная повторная загрузка того же файла —
дедупликация вернёт трек, а вот обложку и правку метаданных не вернёт.

## Заметки на exp-версии Elysia 2.0

Порядок аргументов роута инвертирован против v1 (схема `{ body }` идёт
**вторым**, хендлер третьим). PATCH-роут, написанный в старом порядке, молча
возвращал схему вместо исполнения хендлера — тесты это ловят.
exact-mirror пишет в stderr warning про TypeCompiler при первом использовании
`t.Optional` — не влияет на работу, известный шум exp-билда.

## Обложки

`extractCover()` вынимает из тегов первую jpeg/png картинку. Форматы
встречаются и другие, но обложка нужна маленькая, поэтому gif/tiff пропускаем
молча. Файл кладётся в `storage/cover/{id}.{ext}`, путь записывается в колонку
`cover_path`, и `GET /cover/:id` отдаёт его с Content-Type по расширению.
Отсутствие обложки — 404, это нормальное состояние трека, а не ошибка.

`?w=<пиксели>` (16…512) отдаёт превью: sharp-ресайз с дисковым кэшем в
`tmp/cover-cache/`, который чистится перезагрузкой. Виджет рисует до 200 строк
плейлиста, и без превью каждая тянула бы полный джепег из тегов. Вне коридора
отдаётся оригинал. Битый файл, который sharp не смог отмасштабировать,
отдаётся как есть — падать из-за обложки серверу нельзя.

Никогда не бросает: битая обложка — не повод отказывать треку, звук уже
проверен и лежит на месте.
