# Развёртывание

Два способа поставить MusicLib: обычный (bun + node_modules, управляется через
mise) и прод-сборка в один файл. Первый нужен на машине, где есть рабочее
окружение и omarchy; второй — там, где ставить нечего или не хочется.

## Обычная установка

```sh
git clone https://github.com/Krol-X/music-lib.git
cd music-lib
mise trust
mise run install
mise run start
```

Подробности — в [../README.md](../README.md). Здесь только то, что важно при
переносе на другую машину:

- проект может лежать где угодно, `install.sh` подставляет фактический путь в
  systemd-юниты. Но **если перенести папку после установки, юниты останутся
  со старым путём** — прогоните `mise run install` ещё раз;
- `storage/` (база, opus, обложки) в git не попадает, при переносе переносите
  его отдельно — это и есть библиотека;
- плагин ставится симлинком на репозиторий. Если предпочтёте копию —
  положите её сами и правьте осторожно: копия разъезжается с исходниками.

## Прод-сборка в один файл

```sh
mise run build     # → dist/music-lib
```

`bun build --compile` со встроенным bun: на целевой машине не нужны ни bun,
ни `node_modules`, ни копия репозитория. Нужен **только ffmpeg** — он зовётся
subprocess'ом и встроить его в бинарник нельзя.

```sh
MUSICLIB_STORAGE=/srv/music ./music-lib
```

Мост (`player/bridge.mjs`) в бинарник **не входит**: это отдельный процесс,
которому нужен mpv и dbus. На машине с omarchy он ставится обычным способом; на
машине без виджета музыку играть нечем и незачем — библиотека доступна по HTTP.

### Что пришлось изменить ради сборки

**sharp грузится лениво** (`src/app.ts`). Он нативный: `bun build --compile`
не вкомпиливает `.node`, и бинарник падал на старте с `Could not load the
"sharp" module`. Теперь `loadSharp()` подгружает модуль при первом запросе
превью и запоминает результат, включая неудачу. Если sharp нет, сервер
поднимается, а `/cover/:id?w=` отдаёт оригинал обложки: fallback на оригинал
там был и раньше, просто раньше он срабатывал только на битом файле.

**TypeBox подключается явно** (`src/typebox-setup.ts`). Elysia по умолчанию
берёт TypeBox синхронным `require("typebox/type")` в рантайме. Бандлер такой
вызов не разбирает, и бинарник падал с `Cannot find module 'typebox/type'`.
`setupTypebox({ typebox: { type, system } })` делает то же самое связкой,
известной бандлеру, — и пакет добавляется в зависимости явно, а не транзитивно.

Модуль с этой регистрацией импортируется **первым** в `src/index.ts`: схемы
(`t.Object(...)`) строятся прямо в теле `src/app.ts`, и TypeBox должен быть
подключён до этого.

**Миграции встраиваются в бандл.** Рядом с бинарником нет ни файлов миграций,
ни каталога `src`, а `import.meta.dir` указывает внутрь образа — обычный путь
«прочитать каталог миграций» давал `ENOENT: scandir '/$bunfs/root/migrations'`.
`scripts/build.sh` генерирует временную точку входа, которая импортирует
миграции как обычные модули (бандлер встроит их) и отдаёт их knex через
`migrationSource` вместо чтения каталога.

Точка входа кладётся во временный каталог **вне проекта**: в `tsconfig.json` нет
`include`, поэтому `tsc` проверяет все `.ts` подряд и сгенерированный файл
ронял бы `bun run typecheck` в чистом клоне.

**Диалекты knex помечены внешними.** Knex делает `require()` всех диалектов
(mssql, oracle, postgres, mariadb, cockroachdb, redshift) даже при работе с
sqlite. Не установленные optional-зависимости бандлер разрешить не может, и
сборка падала на первом же из них — отсюда длинный список `--external`.

**`src/index.ts` больше не создаёт БД при импорте.** Запуск вынесен в
экспортируемую `startServer(db?)`, а база подключается динамически и только
если не передана. Иначе точка входа бинарника создавала бы лишнее соединение с
невалидным путём к миграциям.

### Проверка сборки

`scripts/build.sh` не просто собирает, а проверяет результат: поднимает
бинарник на отдельном порту с временной базой, ждёт ответа на `/` и
`/tracks`, и только затем рапортует об успехе. Бинарник, который не стартует,
обнаруживается на своей машине, а не на чужой.

### Чего в бинарнике нет

| нет | чем заменить | последствие |
| --- | --- | --- |
| ffmpeg | поставить системно | без него не работает загрузка треков |
| sharp | поставить `node_modules` рядом или мириться с оригиналами обложек | нет превью `?w=`, в плейлисте тянется полный джепег на строку |
| мост `bridge.mjs` | обычная установка | без omarchy музыку играть нечем |

## Обновление бинарника

```sh
git pull && mise run build
```

Миграции уже внутри бинарника, поэтому `MUSICLIB_DB` можно указывать на
существующую базу — пересоздавать не нужно.
