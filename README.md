# MusicLib

Личная аудиобиблиотека для Omarchy: загружаешь треки, они конвертируются в
Opus с разумным битрейтом, а в панели рабочего стола появляется виджет с
плейлистом, который играет музыку через MPRIS — как любой другой плеер.

![omarchy](https://img.shields.io/badge/desktop-omarchy-6c5ce7) ![license](https://img.shields.io/badge/license-MIT-8b8b8b)

## Что это

Три части, которые работают вместе, но не связаны жёстко:

| часть | где | что делает |
| --- | --- | --- |
| **сервер** | `src/` | хранит файлы и метаданные, отдаёт по HTTP. Помнит только библиотеку, не воспроизведение |
| **мост** | `player/` | процесс-плеер `org.mpris.MediaPlayer2.musiclib`. Внутри mpv, снаружи обычный MPRIS |
| **виджет** | `desktop-plugin/` | клон `omarchy.media` с плейлистом, заливкой и правкой прямо в панеле |

Пульт не пришлось писать: `omarchy.media` в баре Omarchy — обычный MPRIS-клиент
и находит мост на session bus сам. Сервер наружу не светится (по умолчанию
`127.0.0.1`) — библиотека приватная по устройству, а не только по настройке.

## Возможности

- **Заливка из виджета** — выбор файлов через `zenity`, конвертация с
  прогрессом, дедупликация по SHA-256: тот же файл дважды не грузится.
- **Битрейт по факту, а не по тегу.** Измеряется, где реально обрезан исходник,
  и подбирается битрейт. 320k MP3 не конвертируется в 128k Opus «на автомате» —
  это потеря, а не выигрыш.
- **Защита от битых файлов.** Обрезанный MP3 даёт от ffmpeg валидный код 0 и
  в 20 раз более короткий Opus; такое отсекается сверкой длительности и
  размера.
- **Стриминг с Range** — перемотка в плеере мгновенная, файл не грузится целиком.
- **Обложки из тегов** с превью для плейлиста: 200 строк не тянут 200 джепегов.
- **Учёт прослушивания** — после 30 секунд реального звучания трек штампуется,
  и режим «Recent» поднимает его по-живому.
- **Резюм позиции** — рестарт моста не теряет место и не включает звук сам.
- **Очередь и список — одно и то же.** Next идёт ровно по нарисованной строке,
  а не по похожему треку (об этом стоит прочитать [docs/widget.md](docs/widget.md)).

## Требования

Обязательное:

| что | зачем | Arch / Omarchy |
| --- | --- | --- |
| **ffmpeg** | конвертация, замер спектра, проверка файлов | `sudo pacman -S ffmpeg` |
| **bun** | сервер и мост | через `mise` |

Для музыки:

| что | зачем | Arch / Omarchy |
| --- | --- | --- |
| **mpv** | играет треки | `sudo pacman -S mpv` |
| **quickshell** | виджет в баре | уже есть в Omarchy |
| **python3** | заливка из виджета | `sudo pacman -S python` |
| **zenity** | диалог выбора файлов | `sudo pacman -S zenity` |

Без `mpv` сервер работает, но музыку играть нечем. Без `quickshell` — то же
самое: библиотекой можно пользоваться по HTTP, просто не из панели.

Все проверки одной командой:

```sh
mise run doctor
```

## Установка

```sh
git clone https://github.com/Krol-X/music-lib.git
cd music-lib
mise trust          # один раз: разрешить конфиг проекта
mise run install    # зависимости, systemd-юниты, плагин в оболочку
mise run start      # запустить сервер и плеер
```

`sudo` не нужен: всё ставится в `~/.config`.

**Важно про плагин.** `mise run install` кладёт в
`~/.config/omarchy/plugins/krol.media` **симлинк** на каталог
`desktop-plugin/` в этом репозитории, а не копию. Это не формальность: копия
разъезжается с исходниками, и правки виджета молча не доезжают — а выглядит
это как «ничего не изменилось». Если скрипт нашёл вместо ссылки старую копию,
он откладывает её в `~/.local/state/music-lib/plugin-backups/` (именно за
пределами каталога плагинов: оболочка перебирает тот каталог целиком и
зарегистрировала бы копию как ещё один плагин с тем же id).

**Важно про путь.** Репозиторий может лежать где угодно: `install.sh` подставляет
фактический путь в systemd-юниты. Поэтому `git pull` в этой папке безопасен —
юниты переживают переезд только если не переносить папку вручную после
установки; перенёс — прогони `mise run install` ещё раз.

### Если без mise

```sh
bun install --frozen-lockfile
cp systemd/music-lib.service.in systemd/music-lib-player.service.in ~/.config/systemd/user/
# в обеих замени __MUSICLIB_DIR__ и __BUN_BIN__ на реальные значения
systemctl --user daemon-reload
systemctl --user enable --now music-lib.service music-lib-player.service
```

## Использование

Клик по виджету в баре — play/pause, правая кнопка — попап с плейлистом:

| действие | как |
| --- | --- |
| играть трек | левый клик по строке |
| сортировка | кнопка режима (`Title` / `Recent` / `Newest`) и кнопка направления ↑/↓ |
| поиск | поле фильтра по подстроке |
| залить | кнопка «залить» → выбор файлов |
| правка тегов | правый клик по строке |
| удалить | «удалить» в форме правки, дважды |

Сортировка влияет и на список, и на очередь плеера: Next всегда идёт по
нарисованному. Режим `Recent` показывает только то, что реально слушалось, и
поднимает трек сразу, как накопил 30 секунд.

### Переменные окружения

Все необязательные:

| переменная | по умолчанию | что задаёт |
| --- | --- | --- |
| `MUSICLIB_HOST` | `127.0.0.1` | интерфейс: наружу лучше не светить |
| `MUSICLIB_PORT` | `3000` | порт |
| `MUSICLIB_DB` | `./storage/music.sqlite` | путь к базе |
| `MUSICLIB_STORAGE` | `./storage` | каталог opus и обложек |
| `MUSICLIB_SERVER` | `http://127.0.0.1:3000` | адрес сервера для моста |
| `MUSICLIB_PUSH` | сокет в `$XDG_RUNTIME_DIR` | канал событий в виджет |
| `MUSICLIB_SORT` | сокет в `$XDG_RUNTIME_DIR` | канал сортировки |

## Команды

```sh
mise run doctor        # проверить зависимости
mise run install       # поставить юниты и плагин
mise run start         # запустить (и включить автозапуск в логине)
mise run stop          # остановить

mise run status        # состояние сервисов и что играет
mise run logs          # живой журнал
mise run pull-plugin   # после правки виджета: обновить его в оболочке
mise run dev           # сервер в foreground с перезапуском
mise run test          # тесты
mise run ci            # типы + тесты
mise run build         # собрать сервер в один бинарник (dist/)
mise run uninstall     # снять юниты и плагин (данные не трогает)
```

## Прод-сборка: один файл

Обычный запуск требует bun и `node_modules`. Если машина чужая (NAS, контейнер,
голый сервер), есть вариант без них — один исполняемый файл со встроенным bun:

```sh
mise run build        # → dist/music-lib, ~89 МБ
```

Дальше файл копируется куда угодно и запускается как есть:

```sh
MUSICLIB_STORAGE=/srv/music ./music-lib
```

Что нужно на целевой машине:

- **ffmpeg** — и только. Он зовётся subprocess'ом, в бинарник не встроен и
  встроить его нельзя;
- сам **мост** (`player/bridge.mjs`) в бинарник не входит: он ходит в mpv и
  dbus-next, это другой процесс. На omarchy он ставится как обычно через
  `mise run install`, а на целевой машине без виджета он и не нужен.

Чем пришлось заплатить, чтобы это работало:

- **sharp не встраивается** — нативный модуль (`.node`), который `bun build
  --compile` не умеет вкомпилировать. Он грузится лениво, и если его нет,
  сервер поднимается, а `/cover/:id?w=` отдаёт оригинал обложки вместо
  превью. Всё остальное работает как обычно.
- **TypeBox подключается явно** (`src/typebox-setup.ts`): Elysia берёт его
  синхронным `require` в рантайме, который бандлер не разбирает, — без
  явной регистрации бинарник падал бы на старте.
- **Миграции встраиваются в бандл** как обычные модули и отдаются knex через
  `migrationSource`: файлов миграций рядом с бинарником нет, и путь
  `import.meta.dir/migrations` внутри образа не существует.

Сборка сама себя проверяет: поднимает бинарник на отдельном порту с
временной базой и убеждается, что `/` и `/tracks` отвечают. Бинарник, который
не стартует, обнаруживается на своей машине, а не на чужой.

## Где что лежит

```
src/            сервер: HTTP, конвертация, теги, БД
  audio/        разбор файлов: качество, спектр, валидация, теги
  db/           knex + свой диалект для bun:sqlite, миграции
player/         MPRIS-мост поверх mpv
desktop-plugin/ виджет omarchy (исходник симлинком ставится в оболочку)
systemd/        шаблоны юнитов: путь подставляет install.sh
scripts/        doctor, install, uninstall, link-plugin
storage/        БД, opus, обложки — в git НЕ попадает (см. .gitignore)
docs/           подробности: API, пайплайн, мост, виджет
```
